# Version 0.7.1 Review-Card and Standard-Part Discovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship version 0.7.1 with model-hash-addressed immutable Design Lesson review cards and mandatory semantic authoritative-source expansion after applicable structured standard-part misses.

**Architecture:** Candidate validation remains a pre-publication operation and never writes a card on error. Valid cards use a model-SHA-addressed filename while existing state-bound legacy `review.json` cards remain readable and untouched. The project-owned standard-part skill gains a semantic expansion stage after structured providers, without adding a runtime search dependency or a fixed component taxonomy.

**Tech Stack:** Python 3.12+, pytest, pathlib, canonical JSON and secure atomic filesystem helpers, Markdown Agent Skills, uv/hatchling, GitHub Actions and GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-09-01-v0.7.1-review-card-and-standard-part-discovery-design.md`

## Global Constraints

- Product source changes occur only in the nested `ai-mechanical-design-agent` repository.
- Preserve PostgreSQL as authority and Neo4j as a rebuildable projection; this change adds no database migration.
- Preserve the approval, validation, publication-selection, standard-part provenance, and public-release contracts.
- Support macOS and Windows with Python 3.12 or newer and platform-neutral `pathlib` paths.
- Do not rewrite, rename, or delete existing immutable review-card evidence.
- Do not add media dependencies, remote access, telemetry, or a new web-search runtime dependency.
- Release only after focused tests, the complete supported offline suite, distribution checks, skill validation, clean install checks, and required GitHub checks pass.
