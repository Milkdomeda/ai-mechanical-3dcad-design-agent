## Architecture content

The diagram must distinguish responsibilities rather than presenting every MCP
tool as an independent subsystem:

1. The mechanical engineer supplies requirements, constraints, direction
   approval, and final confirmation.
2. The coding agent or LLM performs requirement interpretation, engineering
   reasoning, planning, and orchestration.
3. Design MCP owns deterministic session state, knowledge retrieval,
   standard-part registration, result recording, confirmation state, and
   Design Lesson review decisions. It does not contain an LLM.
4. External FreeCAD GUI MCP performs interactive CAD inspection and edits.
5. Pinned FreeCADCmd performs controlled exact-model validation and never
   replaces engineering judgment.
6. Each design session keeps `design.json`, one authoritative `model.FCStd`,
   source snapshots, validation evidence, outputs, and an optional immutable
   lesson-review card together in its workspace.
7. Structured standard-part providers are searched first; a structured miss
   can expand to authoritative manufacturers, standards bodies, industry
   associations, or attributable authorized distributors.
8. PostgreSQL stores only Product Families, Knowledge Assertions, and Design
   Lessons. Neo4j is an optional rebuild-only projection.
9. Validation failures return to the agent for correction. Final confirmation
   triggers automatic Design Lesson evaluation and, only when material lessons
   exist, one explicit publication decision.

## Visual organization

- Top: engineer input and approval boundary.
- Center: coding agent / LLM orchestration.
- Right: Design MCP, FreeCAD GUI MCP, and pinned FreeCADCmd validation.
- Center-lower: design-session workspace and standard-part discovery.
- Left: durable knowledge and knowledge acquisition.
- Bottom-right: validated design output and Design Lesson feedback.
- Foundation: macOS and Windows, Python 3.12+, local loopback services,
  portable configuration, and deterministic artifacts.

Connectors must name the important control and evidence flows. The diagram must
not claim that pgvector, Neo4j, PostgreSQL, or any remote service is required for
CAD creation and validation.
